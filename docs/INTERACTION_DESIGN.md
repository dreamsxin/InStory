# InStory 交互设计说明

版本：v1.1  
日期：2026-09-06  
状态：MVP 交互基线；第 11–13 章记录已实现的实际流程与待补齐项

本文档定义 InStory MVP 阶段的客户端交互模型。产品核心不再是“每一步都要求用户选择”，而是“阅读为主，入戏为触发”：用户默认连续阅读，在关键时刻或主动点击按钮时进入故事世界参与行动。

第 1–10 章是设计基线（意图与原则）。第 11 章之后描述当前代码里真实存在的路由、控件和流程，以及尚未补齐的部分；两者不一致时，以第 11 章之后为现状。

## 1. 设计原则

- 阅读优先：用户应先获得小说式连续阅读体验，不被频繁选择打断。
- 随时入戏：用户可以在任意阅读位置点击“入戏”接管当前场景。
- 关键介入：系统在危机、询问、线索、路线分歧和章节转折处提示可参与。
- 角色即上下文：“我的角色”不是装饰资料，而是 AI 生成互动时的身份设定。
- 创作轻量化：MVP 只提供必要的故事世界和角色配置，不做复杂工作流。
- 移动端优先：参考 AI 角色聊天产品的移动端布局，但保持 InStory 的阅读叙事定位。

## 2. 主信息架构

MVP 客户端保留三个核心入口：

1. 故事
   - 浏览可进入的故事。
   - 这是探索入口，面向所有已可进入的作品，不承担“我的作品管理”。
   - 展示题材、简介、AI 自由度、世界状态。
   - 进入前选择“我的角色”。

2. 继续阅读
   - 展示最近会话。
   - 快速回到上次阅读位置。
   - 显示当前故事、当前角色、最近关键节点。

3. 创作
   - 普通用户的创作控制台。
   - 分为 `角色库` 和 `故事工作台` 两层。
   - 角色库展示和创建“我的角色”。
   - 故事工作台展示和创建“我的故事”，管理世界观、起点场景、故事演员、剧情锚点。
   - 创建故事时只能选择自己创建的角色作为故事演员。
   - 选择入戏体验模式：剧本入戏、共演入戏、即兴入戏。
   - MVP 阶段保持表单化，不做复杂可视化编排。

移动端可使用底部 Tab：`故事`、`继续`、`创作`。桌面端可使用顶部导航。`角色` 不作为独立主导航，也不做独立角色聊天入口；角色对话应发生在用户进入故事后的入戏场景里。

## 3. 首页布局

首页应同时回答三个问题：

- 我能进入哪个世界？
- 我准备用哪个角色进入？
- 我上次读到哪里？

推荐结构：

```text
Header
  Brand
  当前角色快捷入口

Main
  继续阅读
  故事世界列表
  我的角色快捷区

Create Entry
  创建角色
  创建故事世界
```

参考项目的可借鉴模式：

- 用 Feed 或卡片列表承载内容发现。
- 用底部弹层或浮层承载创建入口。
- 用头像、标签和短描述快速表达角色身份。
- 在核心页面保留当前身份入口。

不照搬的部分：

- 不把产品变成纯聊天列表。
- 不把图片生成、群聊、直播等复杂能力放入 MVP。
- 不用强装饰卡片压过阅读正文。

## 4. 我的角色

### 4.1 角色列表

角色卡片展示：

- 头像或默认形象
- 名称
- 性别
- 性格摘要
- 身份背景摘要
- 最近使用故事

主要操作：

- 新建角色
- 编辑角色
- 删除角色
- 设为默认入戏角色
- 进入故事时选择

### 4.2 创建角色

这里的“角色”指读者自己的入戏身份，不是作者在故事里创建的 NPC 或原生角色。它的作用是告诉 AI：读者以什么名字、性格、背景和行为倾向进入故事。

MVP 表单字段：

- 名称：用户在故事中的名字。
- 性别：可选，允许用户自由填写或选择“不设定”。
- 性格：给 AI 使用的行为倾向。
- 头像或形象 URL：MVP 可先用 URL 或默认头像。
- 身份背景：用户是谁，来自哪里，有什么能力或限制。
- AI 互动描述：补充说明 AI 在故事中应如何理解该角色。
- 可见性：仅自己可见或公开可展示。

表单提示应强调“这些内容会影响 AI 如何写你”，避免用户误以为只是个人资料。

MVP 中角色管理位于 `创作 -> 角色库`。独立 `角色` 导航暂不保留，避免把 InStory 误导成普通 AI 角色聊天产品。后续若增加“角色探索”，也应作为从角色进入故事的发现入口，而不是脱离故事的聊天大厅。

### 4.3 角色选择

进入故事前弹出角色选择：

```text
进入《雨夜旧宅》

选择你的入戏身份
  林向晚
  沈既白
  新建角色

按钮
  以此角色进入
```

如果用户没有角色：

- 展示快速创建表单。
- 允许使用默认“陌生来客”先进入。

## 5. 阅读器

阅读器包含两种状态：阅读模式和入戏模式。

### 5.1 阅读模式

默认状态。用户像看小说一样连续阅读。

页面结构：

```text
顶部
  返回
  故事标题
  当前角色胶囊

正文
  连续段落
  NPC 对话
  场景变化
  关键线索提示

悬浮操作
  继续阅读
  入戏行动
  状态
  记忆
```

阅读模式不强制用户每段都选择。AI 可生成多个自然段或一个小节，并在适合的位置附带介入节点。

MVP 当前实现采用“阅读优先工具坞”：

- `继续阅读` 是主操作，按当前角色倾向自然推进下一小节。
- `入戏行动` 是次操作，展开行动面板后再显示建议行动和自由输入。
- `状态` 和 `记忆` 不常驻占屏，只通过浮动工具坞按需展开。
- `沉浸阅读` 收起信息栏只留正文；工具坞常驻，所以出口和信息栏随时能召回。
- 顶栏最左是 `← 书架`：阅读页必须有一条离开的路，不能只靠浏览器后退。
- 正文按窗口加载，更早的回合用 `载入更早的回合` 取回；换地点时插入场景分隔。
- 每个故事可配置阅读装帧（经典书页 / 西方幻想 / 东方水墨 / 哥特悬疑 / 赛博未来），边框画在滚动窗口上，正文在框内滚动。
- 手机竖屏下工具坞固定在底部安全区上方，面板从底部浮出；手机横屏下工具坞靠右上，面板靠右侧浮出，避免遮挡正文阅读区。

### 5.2 入戏按钮

按钮目标：让用户随时接管当前场景。

移动端位置：

- 右下角悬浮按钮。
- 避开输入法和系统安全区。

桌面端位置：

- 阅读区右侧。
- 或底部工具栏。

文案可根据上下文变化：

- 入戏
- 接管这一幕
- 我要行动
- 和角色对话
- 改变剧情

### 5.3 关键介入节点

系统可在以下场景生成介入提示：

- NPC 向用户发问。
- 用户发现线索。
- 危机逼近。
- 路线出现分歧。
- 角色关系出现变化。
- 章节进入转折点。

提示样式应低打扰：

```text
陆清河停下脚步，回头看你。

你可以继续阅读，也可以入戏改变这一幕。

[继续阅读] [入戏参与]
```

如果用户选择继续阅读，AI 应按当前角色默认倾向推进，不应强制等待。

### 5.4 入戏模式

触发方式：

- 点击常驻“入戏”按钮。
- 点击关键节点的“入戏参与”。
- 点击某个系统建议行动。

入戏面板内容：

- 当前角色
- 当前场景
- 可选行动建议
- 自由输入框
- 提交按钮

行动类型：

- 说一句话
- 做一个动作
- 观察环境
- 使用物品
- 更换角色，MVP 可先不支持会话中更换

提交后：

- 服务端生成入戏结果。
- 更新世界状态、关系、线索、记忆。
- 将结果写回正文。
- 回到阅读模式。

### 5.5 交互与叙事边界

“每一步都要选择”不是 InStory 的目标体验。若阅读器频繁停在选项列表，通常同时说明两个问题：

- 交互设计问题：把选项放在主阅读流中，会把小说阅读变成问答式流程。
- 叙事模型问题：故事世界、剧情锚点和生成协议还没有支持段落式推进与关键节点判断。

因此 MVP 的落地策略是先在 UI 上把选择降级为“介入建议”，再在服务端逐步拆分 `read_segment` 与 `intervention_turn`。用户不操作时，故事也必须能够自然推进；用户主动介入时，AI 才读取角色设定、当前状态和建议行动生成互动结果。

阅读模式的内容长度应由作品配置驱动。作者可以设置默认推进长度，系统据此生成一个完整阅读小节；如果作者已经为当前选择配置了后续正文，应优先展示作者预设，再由 AI 做局部个性化补写。

UI 层不能假设 HeroUI 会自动完成阅读器自适应。HeroUI 适合承载按钮、卡片、表单、选择器和弹层等组件；阅读器的 App Shell、横竖屏布局、安全区、正文宽度、文本断行和工具坞位置必须由 InStory 自己定义。

## 6. 继续阅读

继续阅读入口展示最近会话：

- 故事标题
- 当前角色
- 最近段落摘要
- 更新时间
- 关键节点数量

点击后直接回到阅读器。

## 7. 创作入口

创作入口包含两类创建能力，必须在文案上区分清楚：

- 创建入戏角色：给读者自己使用，进入故事时作为“我是谁”的上下文。
- 创建故事世界：给其他读者进入，包含封面、世界设定、起点场景、故事演员和 AI 体验配置。

创作入口必须和故事探索入口分离：

- `故事`：探索所有可进入的故事，包含平台示例故事和其他用户发布或可见的故事。
- `创作`：用户控制台，包含 `我的故事` 和 `我的角色`，用于创建、查看和后续编辑自己的内容。
- `管理后台`：管理员和运营工具，不作为普通用户创作入口，不使用用户侧创作表单。

参考项目的创建入口可以抽象为底部弹层：

```text
创建

角色
故事世界
草稿
创作指南
```

MVP 只启用：

- 创建角色
- 创建故事，配置故事 ID、标题、标语、封面图、类型、世界前提、起点场景和世界规则
- 从已有角色中选择故事演员，AI 会模拟这些演员和读者对话或互动
- 选择入戏体验模式，作为作者创建故事时的核心体验开关
- 选择默认生成长度，控制读者每次继续阅读获得的正文规模
- 保存后回到故事世界列表，用户可以立即选择角色进入试玩

暂缓：

- 图片生成
- 群聊
- 作品动态
- 复杂草稿系统
- 创作者收益看板和提现
- 发布审核和积分体系

### 7.1 创建故事表单

创建故事应分成三段，避免用户一开始面对完整创作后台：

1. 基础展示
   - 故事 ID
   - 标题
   - 标语
   - 类型
   - 封面图 URL
   - 可见性：仅自己可见、公开到故事探索

2. 世界入口
   - 世界前提
   - 起点地点
   - 起点场景描述
   - 世界规则

3. 故事演员
   - 从当前用户自己的角色库选择一个或多个角色。
   - 创建故事时复制为故事内角色快照。
   - 读者输入动作或对话后，AI 按这些演员的性格、目标和约束做出回应。
   - MVP 先复用角色基础人设；后续再开放故事内重设项，例如故事身份、与读者关系、秘密、不可透露信息、当前目标和行为边界。

4. AI 体验
   - 入戏体验模式
   - 默认生成长度
   - AI 自由度

创建完成后默认仅自己可见，出现在 `创作 -> 我的故事`。只有设置为公开的故事才进入 `故事` 探索入口。MVP 不处理正式发布、审核、积分和收益，只验证用户能否顺畅完成“创建故事 -> 公开或试玩 -> 选择角色 -> 进入故事 -> 入戏互动”的闭环。

我的故事管理在 MVP 阶段提供展开式编辑：

- 列表展示标题、标语、类型。
- 展开后可编辑故事展示信息、可见性、世界前提、起点场景、世界规则、入戏体验模式、默认生成长度和 AI 自由度。
- 展开后可选择一个入戏身份试玩故事，直接进入阅读器检查开场体验。
- 可以删除自己创建的故事；平台示例故事和其他用户故事不可删除。
- 删除故事和角色前需要二次确认，降低移动端误触风险。
- 故事演员的故事内重设暂缓，下一步再增加独立演员配置界面。

## 8. 管理后台与客户端的边界

客户端：

- 面向普通用户。
- 负责阅读、入戏、我的角色、轻量创作。

管理后台：

- 面向开发者和运营。
- 负责模型配置、Provider 验证、会话审计和运行状态观察。
- 入口是账号栏的 `管理控制台` 链接，只对 `admin` 角色出现；页面自身也按角色拦截（见 §11）。

不要把管理后台设计成创作入口。普通用户创建故事必须从客户端底部 Tab 或顶部导航的 `创作` 进入。

## 9. MVP 落地顺序

1. 更新首页为故事探索 + 继续阅读 + 创作控制台的组合入口。
2. 在创作控制台实现我的角色列表和创建表单。
3. 进入故事前增加角色选择。
4. 阅读器增加当前角色胶囊。
5. 阅读器增加常驻“入戏”按钮。
6. 将当前回合式输入收敛为入戏面板。
7. 服务端增加关键介入节点数据结构。
8. 将叙事生成从单回合推进逐步调整为段落式阅读推进。

## 10. 成功标准

- 用户可以不做选择也能顺畅阅读。
- 用户随时能明确“我是谁”。
- 用户能在关键节点或主动点击按钮后参与故事。
- AI 输出能体现用户角色设定。
- 阅读器不像普通聊天工具，也不像后台管理页面。

## 11. 角色与权限

产品里只有两种账号角色（`users.role`）：`reader` 和 `admin`。"创作者"不是独立角色——任何读者都可以创作，创作能力靠首页的 `创作` Tab 提供，不需要授权。

- 访客：未登录。除 `/login` 外的页面一律重定向到 `/login`。
- 读者（`reader`）：阅读、入戏、管理自己的角色库和故事。看不到、也进不去管理控制台。
- 管理员（`admin`）：读者的全部能力，外加 `/admin` 管理控制台。

管理员身份有三条获得路径，按适用场景排序：

1. `ADMIN_EMAILS`：逗号分隔的邮箱清单。注册时直接成为管理员；清单里的已有账号在下一次登录时自动提权。这是新装环境和已有数据库都适用的方式，不需要连数据库。
2. `PUT /api/admin/users/:userId/role`：已有管理员（或持共享 token 的自动化脚本）把角色发给别人。
3. `ADMIN_TOKEN`：共享凭证，只作为第一个管理员的引导路径和自动化用；浏览器端不使用它。

`/admin` 页面本身按账号角色拦截：未登录跳 `/login`，读者跳回首页。控制台的数据请求由服务端携带 `ADMIN_TOKEN`，与访问者无关，所以页面级校验是唯一的门。

## 12. 各类用户的完整流程

### 12.1 访客

1. 打开任意地址 → 重定向 `/login`。
2. `登录` / `注册` 两个 Tab（`/login?mode=register`）。注册需要邮箱、昵称、密码（≥8 位）。
3. 失败时错误在表单内显示，输入保留。
4. 成功 → 写入 `instory_session` Cookie（httpOnly，30 天）→ 进入首页。

### 12.2 读者：从进门到入戏

1. 首页 `故事` Tab：每张卡片显示类型、AI 自由度、入戏体验、生成长度、阅读装帧。
2. 没读过的故事：在卡片上选「入戏身份」（默认角色，或自己角色库里的角色）→ `进入故事`，创建会话并跳转 `/story/:sessionId`。
3. 读过的故事：卡片变成 `继续故事`，直接回到原会话；`继续` Tab 也列出所有阅读进度。
4. 阅读器里：
   - `继续阅读` 按当前身份自然推进下一小节，正文流式逐字上屏，可中途 `停止生成`。
   - `入戏行动` 展开行动面板：快捷动作、本幕建议（带风险标签）、自由输入（≤2000 字，⌘/Ctrl+Enter 提交）。
   - 工具坞：`状态`（场景、位置、情绪、线索）、`记忆`（存档时间线、`恢复此存档`、`重置会话`）、`行动`、`沉浸阅读`（隐藏信息栏）。
   - 顶栏：`← 书架` 回首页、故事标题、当前身份、今日剩余配额。
   - 换地点时正文出现场景分隔；只加载了一个窗口的回合，更早的用 `载入更早的回合` 取回。
5. 配额用尽或触发限流时，错误显示在行动面板或正文下方，限流会给出可重试的秒数。

### 12.3 读者作为创作者：从建角色到试玩

1. 首页 `创作` Tab → 二级 `角色库` / `故事工作台`。
2. `角色库` → `创建入戏角色`：名称、性别、性格、头像 URL、身份背景、可见性。这些字段是 AI 写"你"的依据，不是个人资料。
3. `故事工作台` → `创建新故事`，四段一次提交：
   - 展示信息：故事 ID（小写字母数字与连字符，≥3 位）、标题、类型、一句话钩子、封面 URL、可见性
   - 世界入口：世界前提、起点地点、起点场景、世界规则（一行一条）
   - 故事演员：从自己的角色库勾选
   - AI 体验：入戏体验、生成长度、AI 自由度、阅读装帧
4. 保存后故事出现在 `我的故事`（默认仅自己可见）。展开可编辑全部字段、`试玩故事`、`删除故事`（二次确认）。
5. 设为 `公开` 后才进入 `故事` 探索入口，其他读者可见。

### 12.4 管理员：从提权到运维

1. 按 §11 拿到 `admin` 角色（本地开发最省事的是 `ADMIN_EMAILS`）。
2. 首页账号栏出现 `管理控制台` 链接 → `/admin`。
3. 控制台分区：模型配置与 `验证当前 Provider`、用量、审核队列（`解决` / `忽略`）、故事基础配置（含阅读装帧）、会话列表。
4. 控制台顶栏 `客户端` 链接回到读者侧。
5. 管理控制台不是创作入口：普通用户建故事只走 `创作` Tab，两侧不共用表单。

## 13. 与设计基线的差距（待补齐）

按当前判断的优先级，尚未做到的部分：

- `试玩故事` 每次都新建会话，反复试玩仍会在 `继续` 里堆积；现在至少可以逐条删除，但作者想"重新检查开场"和"回到上次试玩"之间还没有区分。
- `继续` 卡片在缺少故事元数据时使用兜底值，标签可能与实际配置不符。
- 今日配额只在推进过一次之后才显示。
- 关键介入节点（§5.3）仍由 AI 在正文里附带建议，服务端没有独立的 `read_segment` / `intervention_turn` 拆分。
- 故事演员的“故事内重设”（故事身份、与读者关系、秘密、当前目标）未开放。
- 编辑已有故事/角色时，如果保存失败，表单里显示的是服务端存的旧值，未保留这一次的修改；创建表单已经保留。

已补齐（保留记录，便于回看判断依据）：

- 创建与保存都会在按钮旁给出成功或失败的回执；创建失败时把填过的内容原样送回，不再丢稿。
- 有了 `error.tsx` 和 `not-found.tsx`：失效的阅读进度按 404 呈现，其他异常给出重试和回书架两个出口。
- 破坏性操作的确认标准统一了：`重置会话` 和 `恢复此存档` 与删除故事/角色一样会先问一次，并说明后果不可撤销。
- `继续` 卡片可以删除这段阅读进度（`DELETE /api/sessions/:id`，按 owner 校验，回合与存档一并删除）。
